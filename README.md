# ESCO Outages 1.7.0

Об'єднана версія: календар відключень і перевірка за реле (1.5.x), розрахунки стану за графіком
та режим «прапорець» (1.6.1), дати інтервалів і атрибути для картки годинника (1.4.0).

## Що нового порівняно з 1.5.1 / 1.6.1 / 1.4.0

**Календар `calendar.outages_queue_<черга>`**
- Графік дня зберігається між оновленнями: якщо сервер перепублікував графік без уже минулих
  інтервалів, вони залишаються в календарі (і далі перевіряються за реле). Майбутні інтервали
  беруться з нового графіка: перенесений або скасований зникає.
- Відключення через північ (наприклад 23:00–01:00) не пропадає після зміни доби.
- Інтервали «на завтра» (поле `date` в елементі `outages`) показуються в календарі.
- Значки: ⚡ за планом, 🔴 триває, 🟡 світло є, ✅ було, ❌ не було, 🔴 «Позапланове відключення».
  Поки сигнал від реле триває менше 3 хвилин, значок нейтральний (⚡), без хибного «світло є».

**Сенсори та бінарні сенсори**
- Типізовані сенсори (`timestamp`, `duration`, `date`); `current_outage_*` без відключення мають стан `unknown`.
- Нові: `power_available` (чи має бути світло за графіком) і `power_restore` (коли очікується відновлення).
  Вони оновлюються точно в момент початку/кінця відключення, без додаткових запитів до API.
- `next_outage_exists` («Є наступне відключення») збережено, щоб не зламати наявні автоматизації.
- Атрибути для картки годинника збережені й доповнені: `esco_field`, `line`, `outages`,
  `schedule_status` (`on` / `off` / `missing`), `schedule_updated`, `last_poll`, `next_update`.
- Відповідь «графіка на сьогодні немає» (404 або `date: null`) не вважається помилкою:
  сенсори графіка стають `unavailable`, календар зберігає вже відомий план.
- Масив `outages` необов'язковий: якщо його немає, береться поточне й наступне відключення.

## Фактичне відключення за сутністю (параметри інтеграції)

Поле **«Як сутність повідомляє про відключення»** має два режими:

| Режим | Коли обрати | Що вважається відключенням |
|---|---|---|
| `unavailable` (типово) | Wi-Fi реле (Shelly тощо), яке без напруги стає недоступним | `unavailable` / `unknown` |
| `switch_on` | Перемикач/прапорець `switch.power_outage` | `on` = відключення, `off` = світло є, `unavailable`/`unknown` = немає сигналу (не відключення) |

Відключення фіксується, коли сигнал тримається 3 хвилини; початком вважається момент зміни стану.
Проміжки без сигналу запам'ятовуються й не дають хибного ❌ «не було».

> **Увага тим, хто ставив 1.6.1:** там `switch` за замовчуванням трактувався як прапорець.
> У 1.7.0 режим вибирається явно, типовий — `unavailable`. Відкрийте *Налаштувати* біля
> інтеграції й виберіть `switch_on`, якщо ваша сутність — прапорець `on` = відключення.

## Оновлення

1. Збережіть копію `custom_components/esco_outages`.
2. Замініть папку вмістом архіву, перезапустіть Home Assistant.
3. За потреби відкрийте *Налаштувати* й перевірте сутність та режим.

Застарілі сутності `next_outage`, `outage_schedule` та другий календар `actual_calendar`
прибираються автоматично. Сторонні сутності не чіпаються.

## Обмеження

- Графік дня бачить лише те, що сервер віддав після встановлення цієї версії: події, які зникли раніше, відновити неможливо.
- Bubble Card показує лише поточні та майбутні події; повну добу видно в панелі «Календар» Home Assistant.
- Ідентифікатори сутностей утворюються з назв (наприклад `binary_sensor.power_available_according_to_schedule_queue_4_1`);
  точні значення дивіться у *Налаштування → Пристрої та служби → Сутності*.
- Картка годинника (`esco-outage-clock.js`) не входить до цього архіву.

## Встановлення через HACS або Marketplace

Додайте `https://github.com/tgps-robo/esco-outages` як користувацький репозиторій типу Integration. Установіть інтеграцію, перезапустіть Home Assistant і додайте ESCO Outages у Налаштування → Пристрої та служби. Налаштуйте потрібну чергу та інтервал опитування.

Для ручного встановлення завантажте `esco_outages_1.7.0.zip` зі сторінки Releases і розпакуйте в каталог конфігурації Home Assistant.
